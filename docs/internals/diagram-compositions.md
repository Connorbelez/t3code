# Diagram compositions

## Default shapes only

Compositions are built from stock tldraw shapes and bindings, tagged through `meta`, rather than custom shape utilities. Custom shapes would have to exist identically in the server room, the batch preflight rehearsal, every client editor, and import migration, would make us own their migrations, and would break exported documents outside T3 Code and older clients connected to newer servers. The accepted cost is notation fidelity: UML aggregation and composition share the stock diamond arrowhead, and ER cardinality is one combined midpoint arrow label rather than crow's feet. Revisit this decision if that fidelity becomes the blocker, not to make generated shapes resize themselves.

## Membership and regeneration

A shape belongs to a composition only when its record ID equals the ID the composition derives deterministically for that node or edge part. Edges without an explicit key derive one from their endpoints and kind. Derived IDs exclude diagram identity, so duplicated, exported, and imported diagrams keep their compositions; composition keys are unique per diagram. IDs also carry a composition epoch: a new composition takes the first epoch none of whose frame or member IDs exist, so composing a key again after detaching it starts fresh instead of reclaiming the detached shapes, even once the detached frame is deleted. The composition's frame is presentation: shapes dragged out stay members, shapes drawn inside it are never members, and pasted copies carry the `meta` but not the ID, so they are ordinary shapes.

Regeneration never silently overwrites either side. In graph layouts, existing members keep their positions unless the caller explicitly asks for relayout, and new members are placed around them. Where order is the meaning, such as sequence messages or the contents of a wireframe screen, the kit always relays out those members; the composition's frame never moves. Content merges per node or edge against what was last emitted: an unchanged spec leaves the canvas as it is, including human edits and deletions; a changed spec overwrites only an unedited member; a member changed on both sides fails the whole compose with a conflict. Any change not made by composing is an edit, whether a human or a raw agent batch made it. Text and style changes are edits; moving or resizing is layout and never conflicts, and a rewritten member's size is recomputed from its new content. Removing a composition deletes its members; detaching it strips their composition metadata so they remain as ordinary shapes that regeneration no longer manages. Each member stores its last-emitted spec, so reads report that spec plus whether and how a human edited it instead of parsing shapes back into a spec.

A composition is exactly one diagram batch, so it gets one undo step and one consistent merge check, and it is limited to the batch record cap. Oversized compositions fail rather than splitting across batches; agents split them into several compositions. Composing runs in the connected editor host, which supplies text measurement and the DOM-dependent Mermaid parser, so like any batch it fails without an editor.
